# Mercury Fleet 0.1.0

> **Not published yet.** `@aywengo/mercury-fleet` is still absent from the npm registry, there is
> no `fleet-v0.1.0` tag, and there is no GitHub Release for it. Nothing on this page is installable
> today; Fleet runs from a source checkout with `npm run fleet`. The steps that remain are at the
> bottom.

Fleet manages several independent Mercury instances from one place. It speaks each host's public
HTTP API only: it never opens a Mercury database and never imports Mercury code.

## What this is

The host registry and probe, plus dispatch, routing, reconciliation, event mirroring, input and
cancellation forwarding, and a Prometheus rollup that merges hosts into one exposition.

## Install

Not available. There is no published package to install, so an `npm install` of
`@aywengo/mercury-fleet` fails with `E404` whatever tag is named. From a checkout of this
repository:

```bash
npm run fleet -- hosts list
npm run fleet -- --help
```

Requires Node.js >= 22.18.0. Operator guide: [`fleet/README.md`](../../../fleet/README.md).

## What changed since 0.1.0-rc1

`0.1.0-rc1` was recorded in the changelog but never published, and it could not have been installed
if it had been. Its `package.json` pointed `bin` at `cli.ts` and shipped TypeScript sources, and
Node refuses to strip types from a file under `node_modules` on every version that can strip types
at all. `npm install` would have succeeded and `fleet --version` would have failed.

0.1.0 ships compiled JavaScript in `dist/` with `bin` at `dist/cli.js`, which is what the host has
always done. A test now packs the package, installs it into a throwaway prefix, and runs the binary
a user would run, because 187 source-level tests passed against an artifact that could not start.

## What publishing still requires

Trusted publishing is configured on the npm package page, and the page cannot exist before the
package does. So the first publish needs a credential, and it has to run inside the package:

```bash
cd fleet                      # from the repo root this publishes @aywengo/mercury, not fleet
cp ../LICENSE LICENSE
npm version --no-git-tag-version 0.0.1-bootstrap
npm publish --access public --tag bootstrap
```

Publish a throwaway version, never `0.1.0` itself: npm refuses to publish a version twice, so a
bootstrap at `0.1.0` would consume it and the `fleet-v0.1.0` tag -- the release that carries SLSA
provenance -- could then never be published.

After that the package page exists, trusted publishing can be configured for it, and a
`fleet-v0.1.0` tag needs no secret at all. The release workflow checks the registry rather than
assuming, so it stops refusing on its own the day the package exists.
