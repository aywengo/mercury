# mercuryctl 0.1.0

First release of the remote operator client.

## Install

`mercuryctl` ships in the same package as the host, so installing the host installs the client:

```bash
npm install -g @aywengo/mercury
mercuryctl --version
```

Requires Node.js ≥ 22.18. No server, worker, database or workspace configuration is read by the client,
and none is needed to run it.

Operator guide: [`docs/client.md`](../../client.md). Design and per-milestone status:
[`docs/cli-tui-design.md`](../../cli-tui-design.md).

## What this is

A remote client for Mercury Runs over the public HTTP API. `agents list`; `runs list`, `show`, `create`,
`events`, `watch`, `input`, `cancel`, `retry`; `config profiles`, `config current`; `completion
bash|zsh|fish`; `--version`.

Stable surfaces: JSON field names and exit codes. Human output may change without notice.

Credentials never appear in `argv`, in output, or in a config file's `credential` field. Plain HTTP is
accepted only for loopback. There is no certificate-verification escape hatch; use a profile `caFile`.

## How this release was verified

`npm run typecheck` and `npm test` — 936 tests, 0 failures, 0 skipped — on Node 22.18.0 (the declared
floor, pinned exactly rather than as `22.x`) and on Node 24.x.

Three checks exist because ordinary unit tests could not see what they guard:

- **Clean-install smoke test.** Packs the real tarball, extracts it under a path containing
  `node_modules`, and runs the installed binary there. This is the only check that can see the class of
  defect that made the first published artifact unrunnable: Node refuses to strip types under
  `node_modules`, so a `bin` target written in TypeScript works from a checkout and fails once installed.
- **Release verification against a separately running server.** The client contract tests start a real
  Mercury server as a separate OS process and drive the CLI against it over HTTP — including the SSE
  stream — rather than stubbing the transport. A client that agrees only with its own fake is unproven.
- **TLS tests with generated certificates.** Each case runs with the right CA, no CA, and a *different
  valid* CA. Without the third, a green suite cannot distinguish "the profile's CA is consulted" from
  "verification is switched off".

## Not in this release

The terminal UI (Milestone 5) is designed but not built; it stays gated on demonstrated need.
Package-registry publication beyond this package, and multi-host routing, are deferred.

`bin.mercury` still points at a TypeScript file and so cannot run once installed — see
[#243](https://github.com/aywengo/mercury/issues/243). `mercuryctl` is unaffected.
