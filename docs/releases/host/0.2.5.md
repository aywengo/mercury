# Mercury host 0.2.5

A patch release about identity. `mercury host doctor` now reports whether the worker's OS user holds
GitHub credentials of its own, the nightly skill files proposals through the dedupe path that can
actually find them, and the documentation states the rule a mis-provisioned host broke on 2026-10-23:
a credential profile's token must be the account it claims to be.

## Install

```bash
npm install -g @aywengo/mercury        # 0.2.5
```

Or:

```bash
git clone https://github.com/aywengo/mercury.git
cd mercury
npm ci
```

Or from Homebrew (formula `mercury-ai`; homebrew-core owns `mercury`, the Mercury language compiler):

```bash
brew tap aywengo/mercury https://github.com/aywengo/mercury
brew install mercury-ai
```

Requires Node.js >= 22.18 and `git`. `mercury --version` prints `mercury-host 0.2.5`; `GET /healthz`
reports `"version": "0.2.5"`.

## `host doctor` reports the worker user's GitHub credentials (#1060, PR #1061)

A Mercury host shares its OS user with whoever installed it, so a tool shell that reaches
`$HOME/.config/gh/hosts.yml` or the login keychain acts as that person. `mercury host doctor` now
prints a fifth section:

```
agent credentials: PASS|WARN — …
```

It reads `gh auth status`'s output (the command exits 1 when nothing is logged in, so the exit code
is not the signal) and names the account; on macOS it also reports a `github.com` internet password in
the login keychain. `--json` carries the same result as `agentCredentials`.

## A profile's token must be the identity it claims (#1060, PR #1063)

The 2026-10-23 night filed four proposals as the operator. CP-4 was working: inside the Run the tool
shell saw the Run's `GH_CONFIG_DIR` and `GH_TOKEN`. The profile's secret file simply still held the
operator's PAT from before the host token was swapped for the bot's. `docs/configuration.md` now
states the rule and the one-line check, and `docs/operations.md` makes it a checklist item:

```bash
GH_TOKEN=$(cat ~/.config/mercury/secrets/mercury-nightly.pat) gh api user --jq .login
```

The dedicated-OS-user deployment that removes the host user's credentials from a Run's reach has a
runbook: [`deploy/dedicated-user.md`](../../../deploy/dedicated-user.md) (PR #1062).

## Nightly: dedupe by search terms, and filing only through `propose` (#1053, PR #1054)

Rung 4's duplicate check searched GitHub with the proposal's exact title as a quoted phrase. GitHub
search is token-based, so a title containing `§`, `—` or `:` matched nothing and the check read as
"not filed yet" — the same proposal could be filed again. The source leg now queries the source key and
the title leg queries its distinctive terms, both compared exactly client-side, and a search that
cannot answer still fails closed. The `nightly` and `issue-fix-loop` skills now forbid filing with
`gh issue create` or `gh api …/issues`: a proposal goes through `next.ts propose`, which owns the
dedupe check and the `nightly-source` marker.

## The CLI

`mercuryctl`, the operator client, ships inside this same package — there is no separate CLI artifact
and no separate version to track:

```bash
mercuryctl --version                    # 0.2.5
mercuryctl runs show <runId>            # timeline, events, workspace pointer
```

The CLI talks to the same owner-scoped API the dashboard uses; every endpoint it calls is documented
in [`docs/api.md`](../../api.md).
