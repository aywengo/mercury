# Mercury host 0.2.6

A patch release that makes a fresh host actually run, and lets a bot dispatch through Fleet.

`mercury host service install` used to write one service, running `mercury server`. The server
never claims Runs — `MERCURY_EMBEDDED_WORKER` is honoured only for `dev` — so a host installed from
the installer accepted Runs from Fleet and executed none. Install now writes and enables a worker
service beside the host service on both platforms. Separately, a bot whose config says
`api.via: "fleet"` dispatches through Fleet instead of its own host, with single-flight and
idempotency preserved.

## Install

```bash
npm install -g @aywengo/mercury        # 0.2.6
```

Or:

```bash
git clone https://github.com/aywengo/mercury.git
cd mercury
npm ci
```

Or from Homebrew (formula `mercury-ai`; homebrew-core owns `mercury`, the Mercury language compiler):

```bash
brew tap aywengo/mercury https://github.com/aywengo/mercury
brew install mercury-ai
```

Requires Node.js >= 22.18 and `git`. `mercury --version` prints `mercury-host 0.2.6`; `GET /healthz`
reports `"version": "0.2.6"`.

## A fresh host now runs what it accepts (#1071, PR #1072)

`mercury host service install` wrote one unit, `mercury server`, with
`Environment=MERCURY_EMBEDDED_WORKER=true`. `src/cli.ts` honours that flag only for `dev`, so the
API accepted Runs and no process claimed them. The #929 fresh-host verification run on 0.2.5 caught
it exactly as designed:

```
healthz: PASS - host 0.2.5 ok
healthz (bind 0.0.0.0, dialed 172.17.0.4): PASS - host 0.2.5 ok
smoke primeagent: FAIL - primeagent smoke run run_30da5893f9ea42b1 did not finish in 120000ms
```

The Run sat `QUEUED` with `startedAt: null` and `leaseOwner: null`. Starting `mercury worker` by
hand against the same `mercury.env` claimed both parked smoke Runs immediately, and both completed.

Install now writes two services, and enables both:

| Platform | Host | Worker |
| --- | --- | --- |
| systemd (user) | `mercury.service` — `mercury server` | `mercury-worker.service` — `mercury worker`, `TimeoutStopSec=45` |
| launchd | `com.mercury.host` + `run-host.sh` + `host.log` | `com.mercury.worker` + `run-worker.sh` + `worker.log` |

`MERCURY_EMBEDDED_WORKER` is gone from the generated host unit: the server ignores it, and a flag
that lies is worse than no flag. `mercury host service status` and `... uninstall` cover both
services. The development path (`MERCURY_EMBEDDED_WORKER=true npm run dev`) is unchanged.

**Upgrading an affected host:** `mercury host upgrade` restarts the host service only. Re-run
`mercury host service install` after the upgrade so the worker service exists, or the host will
still accept Runs it cannot execute.

## Bots can dispatch through Fleet (#973, PR #1016)

`api.via: "fleet"` in a bot's config sends its two scheduler calls to Fleet instead of the host:

- `POST /fleet/runs` with the bot's derived key as `Idempotency-Key` (201 new, 200 replay — both
  map to the Fleet Run id), so a crash between dispatch and state-write replays the original Run;
- `GET /fleet/runs?owner=self&limit=&cursor=`, scoped by Fleet to this bot's own bindings, so
  another caller's non-terminal Run on the same host never blocks this bot.

Fleet decides placement; the bot never does. `"fleet"` requires a `fleet` token beside `api` in
`bot-credentials.json` — a different secret from the host token, scoped by Fleet to the hosts the
bot may use — and `mercury host bot validate` refuses the config without it, naming the alias. A
binding Fleet cannot resolve (`UNKNOWN`) counts as non-terminal and blocks the next fire, the same
rule a parked `NEEDS_INPUT` Run follows. The default stays `"host"`.

## The CLI

`mercuryctl`, the operator client, ships inside this same package — there is no separate CLI artifact
and no separate version to track:

```bash
mercuryctl --version                    # 0.2.6
mercuryctl runs show <runId>            # timeline, events, workspace pointer
```

The CLI talks to the same owner-scoped API the dashboard uses; every endpoint it calls is documented
in [`docs/api.md`](../../api.md).
